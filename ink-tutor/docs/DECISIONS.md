# Decisions log

Format: decision — why — alternatives rejected — date. Append; do not rewrite history.

1. **Web app only; no native iOS/macOS.** Owner has no Apple developer account. iPad uses Safari over the LAN with Apple Pencil (pointer events give pressure/tilt). Rejected: SwiftUI + PencilKit (better latency, needs account). 2026-10-23
2. **Fully local by default; cloud (Anthropic/OpenAI) only as an explicit per-session toggle for tier 2.** Recognition never leaves the Mac. Rejected: MyScript iink (best online recognition, but cloud-only, metered, diagrams REST-only). 2026-10-23
3. **Ink stays ink.** The tutor never modifies, snaps or typesets user strokes; it annotates on separate layers in its own hand. Rejected: live typeset "twin" pane; converting sketches to clean shapes as the primary view; inline tutor text between lines. 2026-10-23
4. **Two-tier pipeline.** Tier 1 instant local recognition (mathnote-ocr for math strokes; Qwen3.5-4B for text/CJK; Chandra 2 for photos). Tier 2 Qwen3.6-35B-A3B MLX for tutoring. Rejected: one dense 27B model doing everything (too slow for real-time feel on M3 Pro); frontier-only pipeline (not local). 2026-10-23
5. **Deterministic checkers run before the LLM** and the LLM may not contradict them (it may ask instead). 2026-10-23
6. **Canvas: tldraw SDK** for its editor API (programmatic shapes/annotations, Mermaid → native shapes, export). Caveat: since SDK 4.0 it is source-available with a license key required in production (free hobby key with watermark; dev mode needs no key). **Fallback: Excalidraw (MIT)** if the license becomes a problem; backend is agnostic (strokes + PNG). Hand-rolled canvas (perfect-freehand) acceptable if diagrams become secondary. 2026-10-23
7. **Recordings as fixtures.** Timestamped stroke logs + checkpoint snapshots + `truth`/`expect` fields recorded by the owner; Claude drafts truth from snapshots, owner confirms. Rejected: screen recordings as test data (no coordinates/timing, lossy). 2026-10-24
8. **Voice channel in the final product**, local stack (Silero VAD, Parakeet TDT, Kokoro/Qwen3-TTS), feeding the same session agent; short unprompted speech, barge-in, speech controls the hint ladder. Cloud realtime speech only when the cloud toggle is on. 2026-10-24
9. **Demo scope:** maths + system design + one language on one canvas; accounting T-accounts as a cheap fourth. 2026-10-23

10. **Local tier-2 model is a config var + UI picker, not a hard choice.** `LOCAL_MODEL` selects a manifest entry; runtime swaps the model server with a memory check; Qwen3.6-35B-A3B default, Gemma 4 26B-A4B and Qwen3.8-27B registered. Pick the default after `make judge` on the owner's fixtures. 2026-10-24

17. **Tier 1 = geometry first, then a small VLM per region.** Strokes are grouped into regions (anisotropic gaps, same-row rule, fraction bars); long divisions are found from their "└" bracket and their parts assigned by position; each changed region is read by Qwen3.5-4B (a labelled sheet for divisions), confidence from token probabilities. mathnote-ocr misread the owner's 1/5/0 (kept as an optional extra for later fine-tuning). The 300 ms tier-1 target is not met (2–3.5 s per line); reads start at the debounce and overlap the settle time, so the first mark still lands < 4 s. 2026-10-24

33. **Teacher view: homework, a learning log and a 2–5 sentence summary per student, all on the Mac.** The owner: "the server can store the logs and the teachers can see the progress of the children, if they did the homework". A teacher sets a `Homework` (title, mode, problem, optional due date and final answer) at `/teacher`; students open `/?hw=<id>` (link + QR) and type their first name (remembered per device, changeable); `Session` gains optional `student` and `homework_id` (sessions without homework work as before; the server's copy of the homework sets mode and problem). The **learning log** is computed deterministically (`progress.py`) from what is already stored: feedback events (checker ✓/✗, hints per level incl. explicit level 4, question chips, ghosts and their retracts), the latest readings and the strokes' clock (time on task = first to last ink), plus a small `activity` table the agent's hooks fill with what the feedback table can't tell (each verdict's checker kind, short reading and line box; question answers; corrections). No strokes or images are logged. A mistake counts as fixed when the ✗ line (or one written over the same spot) is later ✓, when its ghost retires, or when a checker retracts its own mark; "finished" = a ✓ line reaches the homework's final answer, else the last checked line is ✓ (`null` for modes no checker can decide, e.g. diagrams). The **summary** is written by the local tier-2 tutor (`Tutor.summarize`, `prompts/progress.md`) from the log only, only when that model is already loaded and no review/recognition is in flight anywhere; new ink cancels a summary being written (the live student wins). Otherwise, or on failure/LaTeX output, a deterministic template from the log. It is generated when a session ends (last socket closed, 15 s grace) or goes idle (no ink for 10 min) and on Refresh, cached per log hash, rewritten only when the log changed. Cloud summaries only when the session's provider is cloud and the teacher asks explicitly ("Refresh with Claude"). **Access:** `/teacher` and `/api/teacher/*` answer on localhost/LAN only; through the tunnel they are refused even with the pairing cookie every student's iPad has, unless `TEACHER_TOKEN` is set (then `?t=` once → HttpOnly cookie). Students only reach `GET /api/homework/{id}` (title/problem/due, never other students). CSV export escapes formula-like cells. Rejected: a separate teacher app or accounts (more to run; one Mac, one class); logging strokes/images for the log (large, and the checkers' verdicts already say what matters); an LLM-only log (non-negotiable 4: the counts are deterministic, the LLM only words them); loading the tutor just to summarise (memory budget). 2026-10-24
34. **Screen tutor server side (Phases 12–13), as built.** One `ScreenSession` per helper id owns perception (last hello, last AX snapshot as an `AXIndex`, last frame per display decoded and dHashed lazily, recent input events), the voice channel over `/ws/screen/{id}` (the canvas's `VoiceSession` and engine) and the guide loop (`guide/loop.py`). Every input answers with a `guide.status` at once ("Got it — planning: …" before any model call); failures are a plain sentence with phase `error`, spoken when voice is on — never silent (owner: "it didn't do anything and didn't show anything"). Locating is AX first (role family + accent-insensitive `title_regex` + path); the VLM (`Tutor.locate`, image pixels → global points via the crop and the frame's origin/scale, snapped to an overlapping AX frame) only on frames whose dHash changed, ≥ 2 s apart. Completion is state-based (`ax_exists`/`ax_value`/`window_title` 300 ms after each snapshot; `vlm_yes_no` as a fallback); a step whose result is already on screen is skipped unless the predicate is about the step's own target. Replans on an app switch (2 snapshots in a row) or an unknown dialog, keeping the goal; version bumps. Spoken commands are parsed by a screen-only parser (`screen/commands.py`: next/back/repeat/stop in EN/ES/CA on ≤ 4-word utterances, "para" alone is not stop; why/what/all-steps for rungs 2/3/4, rung 4 being the plan itself) instead of adding words to `voice/session.py`'s canvas `COMMANDS`; other speech is a goal (no plan) or a question (`Tutor.explain`, new, streamed sentence by sentence) so the canvas `converse` stays as it is. Local only (#32): no `_ask_tutor` lift, cloud `plan`/`locate`/`explain` raise. While the screen session asks tier 2, a canvas review is paused via the canvas agent's own pause/resume and a teacher summary being written yields. A screen session is not a stored `Session` and ends with its last helper. Tested on a synthetic Spanish Excel fixture (5/5 targets by AX, each advance < 1 s after the completing snapshot); live accuracy with Gemma is unmeasured. Rejected: the VLM first (slow, and its boxes are unmeasured); action predicates ("clicked Insert") as completion (break when the user takes another route); a language-model call for commands (latency). 2026-10-24
